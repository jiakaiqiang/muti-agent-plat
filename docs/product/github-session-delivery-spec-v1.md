# GitHub 会话代码交付 Spec v1

状态：2026-09-28 需求已确认，实施中、待完整验收；GitHub 新建入口默认关闭。

关联：[Plan](../design/github-session-delivery-plan-v1.md) | [Tasks](../implementation/github-session-delivery-tasks-v1.md) | [Checklist](../quality/github-session-delivery-checklist-v1.md)。

## 1. 背景与目标

当前会话创建时直接绑定 `local_bridge` 或 `server_local` 目录，并在创建后启动 Agent 分析。系统已有隔离执行和工作区写回，但没有 GitHub 授权、自动克隆、远端分支、PR、CI 门禁或平台合并链路。

目标是让用户在会话中选择本地目录或 GitHub 仓库。GitHub 会话在执行设备上准备独立工作区，Agent 完成任务并通过验证后自动提交、推送和创建 PR；用户在平台审查差异后自行决定是否合并。首版保持单用户部署边界，不建设多租户和完整权限体系。

## 2. 术语

- 执行位置：本机 Local Runtime 或服务器 Runtime；决定代码、Git 操作和凭据的存放位置。
- 代码来源：本地目录或远端仓库；与执行位置是两个独立维度。
- 仓库缓存：同一授权身份下可复用的只读 Git 对象缓存，不承载会话改动。
- 会话工作区：从缓存创建、仅属于一个会话的可写 Git 工作区。
- 基础分支：用户在克隆后选择的 PR 目标分支，默认仓库实际默认分支。
- 任务分支：平台生成并推送的 PR 来源分支；一个未合并的会话交付轮次复用同一分支和 PR。
- 平台验证：平台实际执行并记录的验证命令；Agent 的口头报告不能代替执行结果。
- 冲突编辑器：显示左侧当前分支、右侧待合入分支、第三栏最终结果的统一处理界面。

## 3. 范围与边界

| 执行位置 | 代码来源 | 交付规则 |
| --- | --- | --- |
| 本机 Codex / Claude Code | 已授权本机目录 | 使用本机目录；只交付本地改动，即使目录配置了 GitHub 远端也不自动推送或创建 PR |
| 本机 Codex / Claude Code | GitHub 仓库 | 在用户电脑克隆、执行、保存凭据和完成 Git 操作；自动交付 PR |
| 服务器 Runtime | GitHub 仓库 | 在服务器受控目录克隆、执行、保存加密凭据和完成 Git 操作；自动交付 PR |

- 首版只支持 `github.com`、一个会话一个仓库、站内通知。代码托管和通知渠道保留适配接口。
- 新建服务器 Runtime 会话只提供 GitHub 来源，不再要求用户输入服务器绝对路径；既有服务器目录会话的读取和恢复不因新入口被删除。
- 创建后不能切换代码来源、仓库或本机/服务器执行位置。该规则不限制同一执行位置内已有的 Codex/Claude Runtime 选择能力。
- 多项目仓库不要求用户预选子目录。Agent 根据任务和仓库结构识别；无法唯一确定时在当前会话询问用户，得到答复后继续。
- 首版不支持自动 Fork、GitHub Enterprise、平台逐行评论、平台审批记录、邮件或飞书通知。

## 4. 创建与准备

1. 用户在创建会话时填写任务、选择执行位置和代码来源；选择 GitHub 时输入仓库地址，不选择本地或服务器目录。
2. 系统规范化并校验 `github.com` 仓库地址，拒绝内嵌凭据和不受支持的地址形式。
3. 没有可复用授权时，在会话中展示专用授权控件：跳转 GitHub 授权页，或手动填写访问令牌。令牌输入不进入聊天消息、事件、日志、Agent 上下文或普通会话快照。
4. 同一授权身份和仓库的有效授权自动复用。用户主动断开授权前，删除会话不删除授权。授权失效或仓库无写权限时暂停准备并提示；首版不自动 Fork。
5. 授权后更新仓库缓存并建立会话独立工作区。完成克隆后弹窗列出远端分支，默认选中仓库实际默认分支，而非硬编码 `master`。
6. 用户选定基础分支并完成工作区绑定后，Agent 才开始分析任务。克隆、授权或分支选择失败均不得提前启动 Agent。

## 5. 执行、验证与 PR

- 每个会话拥有独立工作区；缓存仅复用 Git 对象。Agent 的任务执行候选与其他会话以及用户本地目录隔离。
- 基础分支在 Agent 执行期间有新提交时，不主动同步或中断当前任务。
- 平台优先从仓库结构和项目清单识别验证命令。没有可靠命令时询问用户指定验证方式；命令失败或无法运行时暂停推送并在会话中继续修复。
- 验证通过且存在受控代码改动时，系统创建自动命名任务分支和提交，推送并创建 PR；没有代码改动时记录“无需 PR”，不创建空 PR。
- 提交 Author 使用会话发起人的 GitHub 身份，并在提交信息标明平台辅助生成；无法确定合规 Author 身份时，提交前在会话中处理。
- 推送前若远端任务分支已有新提交，自动整合到当前任务分支；整合产生的冲突进入统一冲突编辑器。解决后重新验证再推送。平台外对源目录的修改不纳入受控提交，也不主动删除。
- 同一会话的 PR 未合并时，后续修改更新原分支和原 PR。PR 已合并时创建新分支和 PR。PR 关闭但未合并时尝试重新打开；任务分支已删除则先从会话工作区恢复同名分支。远端拒绝恢复时暂停并说明原因，不静默新建替代 PR。
- 创建或更新 PR 后在平台会话内通知用户，展示 PR 链接、完整文件差异和验证结果。

## 6. 审查、冲突和合并

- 用户在平台审查 PR Diff，自主点击“合并”；系统不得在 PR 创建后或本机重连后自动合并。
- 配置了 GitHub CI 的仓库，检查未完成或失败时禁止合并；没有配置 GitHub CI 时，平台验证通过即可尝试合并。仍须遵守 GitHub 仓库自身的保护和审核规则。
- 点击合并时重新获取 PR、目标分支、检查状态和可合并性。若发生冲突，列出**所有**冲突文件并进入统一冲突编辑器。
- 文本冲突显示当前任务分支、待合入分支及可编辑结果，颜色区分冲突片段和正常代码；支持快捷键采用左侧或右侧内容，也允许直接修改结果。Agent 可以提供建议，但用户逐文件审查并确认。
- 删除、改名、文件模式和二进制冲突也在同一冲突列表中；二进制文件提供保留当前分支或待合入分支版本的选择，不伪装为可逐行编辑文本。
- 全部冲突解决后重新运行原验证命令。失败则暂停提交和推送；通过后生成冲突解决提交、更新原任务分支和 PR，等待 CI，再重新显示“合并”按钮，由用户再次点击。
- 用户处理冲突期间不主动追踪目标分支新提交。最终合并时以 GitHub 当时的状态为准；若新冲突导致拒绝，再进入冲突处理。
- 合并采用 Squash Merge，并在平台展示实际合入的提交 SHA、文件列表和代码差异。

## 7. 恢复、通知与清理

- 授权、克隆、选分支、验证、推送、PR 创建、冲突解决和合并请求均有可查询的持久状态；刷新或服务重启不得丢失待用户动作。
- 相同操作的重试不得重复创建分支、PR、提交或合并。远端状态与本地记录不一致时先对账，再继续。
- 本机 Runtime 离线时不能执行依赖本机凭据与工作区的合并操作；重连后刷新远端状态并重新显示可用操作，不自动续做合并。
- 删除会话只清理该会话的独立工作区和临时草稿，不删除共享缓存、已推送分支、PR 或保存的授权。清理失败应保持可重试并可见。
- 首版通知仅在平台内呈现；通知事件须包含会话、交付轮次、PR 与状态引用，不包含令牌或本机绝对路径。

## 8. 不变量

- GSD-I1：GitHub 仓库是代码来源，不是新的 Workspace Provider 或 Runtime 类型。
- GSD-I2：GitHub 会话的授权、克隆和基础分支选择完成前，Agent 不得分析任务。
- GSD-I3：令牌不进入普通消息、Agent 上下文、Git 远端 URL、命令参数或可见错误。
- GSD-I4：没有平台验证通过的受控候选，不得推送；没有用户点击，不得合并。
- GSD-I5：共享仓库缓存不得承载会话改动；删除一个会话不得破坏其他会话。
- GSD-I6：合并时的 PR head 与用户审查的版本不一致，必须拒绝并刷新，不能合入未审查的新提交。
- GSD-I7：现有本地目录会话不自动获得 GitHub 交付能力。
- GSD-I8：单用户部署下只允许该会话的可信操作者执行合并；没有可信身份边界时不得宣称已实现多人按发起人授权。

## 9. 验收标准

| 编号 | 可验证结果 |
| --- | --- |
| GSD-AC1 | 三种执行位置/代码来源组合符合第 3 节；本地目录会话不自动推送 |
| GSD-AC2 | GitHub 授权两种入口可用、有效授权复用、断开后不复用、令牌不泄露 |
| GSD-AC3 | 仓库无写权限或授权失效时阻止自动交付，并给出可操作提示 |
| GSD-AC4 | 克隆与选定实际默认或其他基础分支之前，没有 Agent 分析调用 |
| GSD-AC5 | 同仓库不同会话共享缓存但使用独立工作区；多项目歧义时询问用户 |
| GSD-AC6 | 验证失败或缺少验证方式时不推送；修复并通过后才继续 |
| GSD-AC7 | 任务完成产生受控提交、分支和 PR；无改动不创建空 PR；Author 与辅助标记正确 |
| GSD-AC8 | 同会话更新未合并 PR；已合并新建；已关闭 PR 重开，分支删除先恢复 |
| GSD-AC9 | 任务执行期间基础分支变化不自动同步；任务分支远端变化在推送前整合 |
| GSD-AC10 | 所有可处理冲突进入统一三栏界面，覆盖文本、删除/改名和二进制选择 |
| GSD-AC11 | 冲突解决后重新验证、更新原 PR、等待 CI，并再次要求用户点击合并 |
| GSD-AC12 | GitHub CI 未完成/失败禁止合并；无 CI 且平台验证通过允许尝试；保护规则不被绕过 |
| GSD-AC13 | Squash Merge 仅作用于用户审查的 head，合并后显示实际合入代码 |
| GSD-AC14 | 离线、重连、重启、重复请求和远端状态变化后保持可恢复且不自动合并 |
| GSD-AC15 | 删除会话清理独立工作区，保留缓存、授权、远端 PR 和分支 |
| GSD-AC16 | Web 与 Desktop 展示准备、PR、验证、冲突和合并状态，站内通知准确 |

## 10. 完成标准

Checklist 中 GSD-AC1 至 GSD-AC16 均有实际证据，且合同、file/PostgreSQL 持久化、Web/Desktop、Local Runtime 和端到端验证通过后，才能将本 Spec 标记为已完成。四件套文档创建不表示功能已实现。
