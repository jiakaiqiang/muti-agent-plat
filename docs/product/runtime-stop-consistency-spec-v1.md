# 执行停止状态一致性与通知 Spec v1

状态：2026-09-15 已完成代码实现、独立 PostgreSQL 故障矩阵和 AC1-AC10 验收。

关联：[Plan](../design/runtime-stop-consistency-plan-v1.md) | [Tasks](../implementation/runtime-stop-consistency-tasks-v1.md) | [Checklist](../quality/runtime-stop-consistency-checklist-v1.md)。

## 1. 目标与范围

修复持久化失败后已结束调用仍被计为活跃、停止状态不能恢复一致以及停止通知重复和过时的问题。Web 与桌面使用同一后端事实和共享状态逻辑，各自保留现有界面布局。

实现由本 SDD 驱动，范围包括 Runtime 监督、Local Runtime 回执、持久化与事件、Session 停止/恢复入口、共享合同和双端停止状态展示。Harness 仅约束交付流程，不增加 Harness 产品模块。

不自动重跑历史任务，不删除历史消息，不修改设备凭据、目录授权或供应商配置，不以延长超时、关闭停止屏障或隐藏消息代替状态修复。

| E1 | 会话 `e608dfdf-9c81-4b32-ac03-5df7a30498d9` 中，调用 `059a6444-c3a4-4c11-a7ce-0a3377cd1fc4` 在 2026-09-14 18:52:08 至 18:56:01（北京时间）产生 43 个不同事件 ID 的部分停止通知 | 后端重复生成业务通知，非前端重复渲染同一个 ID |

E3 已固化为 `runtime.service.spec.ts` 的故障注入回归，并验证修复后的句柄清理、准入屏障和显式核对。E1 的 3 至 6 秒重复节奏及当时完整重传链路仍未证实；不能声明 E3 单独解释全部 43 条通知。当前查询到的 confirmed 也不能反推历史所有内存状态。

已有 [持久化与恢复 Spec](session-persistence-recovery-spec-v1.md) 和 [执行可靠性 Plan](../design/agent-execution-reliability-plan-v1.md) 为前置基线。本专项补齐监督层异常清理、停止聚合与通知一致性；不覆盖或改写旧验收记录。

## 3. 必须保持的不变量

- I1：发送取消、API 返回、Promise 拒绝或连接断开，都不单独证明进程已经结束。
- I2：进程句柄生命周期、可信结束证据、持久化提交结果必须分别记录。
- I3：清理内存句柄不得放开未知停止或待持久化屏障；只有所有目标具备已提交的可信结束事实才结束停止屏障。
- I4：迟到回执只能处理精确绑定的旧调用；不得应用迟到业务结果、写回文件或自动发起新任务。
- I5：同一会话停止与新调用预留之间必须原子互斥；停止前已预留的调用纳入目标集合。
- I6：日志与审计保留，界面折叠不修改原始事件。

## 4. 验收条件

| 编号 | 可验证的要求 |
| --- | --- |
| AC1 | 结束状态持久化抛错时，监督执行句柄必定释放；保留执行结果/结束证据及持久化错误，不以无上下文异常覆盖结果 |
| AC2 | 进程结束未知或结束事实未提交时，继续/重试/新调用预留都拒绝放行；保存失败明确展示为待同步，不能伪称进程仍运行或已可继续 |
| AC3 | 一轮停止拥有稳定 stopRequestId、固定目标调用集合和单调版本；正常运行中的其他调用不能被文案无差别解释为停止未确认；零目标停止立即确认 |
| AC4 | 可信迟到回执及数据库恢复后，目标状态最终一致；结果/stopped 乱序、重复或并发不重复完成、不误确认新调用；重启丢失证据时保持保守状态 |
| AC5 | 停止状态版本、对应事件及 outbox 原子提交；重复回执不生成新版本/新通知；确认提交后才 ACK，ACK 丢失重传仍幂等 |
| AC6 | 未持久化更新的重试有限、有诊断；后台重试不触发模型、业务结果应用或文件写回；依赖恢复后可重新核对，不能永久残留为伪活跃 |
| AC7 | Web/桌面展示当前停止摘要、目标进度、阻塞原因；刷新和 SSE 重连先恢复权威快照，旧事件不得回退较新状态；查询失败显示未知而非可继续 |
| AC8 | 同调用、同代码、同状态的历史重复通知可展开折叠，保留原始顺序和次数；不得跨会话/新停止轮次错误合并；业务失败原因不被回执覆盖 |
| AC9 | 日志能关联 sessionId、stopRequestId、operationId、invocationId、连接及状态版本，区分提交失败、重复接收和重连重放；不记录凭据或完整提示正文 |
| AC10 | 纯内存故障注入、独立 PostgreSQL 并发/重启、真实隔离传输及双端测试通过；合同兼容、迁移和回退经过验证，不改真实业务数据 |

## 5. 成功标准

用户在停止过程中可以知道具体等待什么；已结束的调用不会因一次数据库失败永久占据执行列表。停止事实可靠提交后，用户可经既有显式恢复流程继续；流程本身失败仍显示原失败原因。完成必须以 Checklist 的实际证据为准。
