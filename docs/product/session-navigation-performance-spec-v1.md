## 1. 目标与用户确认

用户报告的是在浏览器的会话列表中选择不同会话时页面卡顿，并补充鼠标也卡，不是仅在一个会话里滚动历史消息。本专项处理跨会话导航、异步竞争及切换引起的渲染压力。

目标：一次选择只产生一轮有效切换；最后一次选择生效；页面读取和群聊执行相互隔离；长会话切换的主线程工作量可控。切换只改变用户正在看的会话，不能改变正在执行的任务。

最初仅授权生成 SDD 文档；用户随后明确要求按四份文档开发，现已进入业务实现。仍不包括服务重启、提交、发布或真实任务重跑。实际通过项及失败项见 Checklist，四件套和代码的存在不表示所有故障已修复。

## 2. 已有依据及证据边界

2026-09-29 在当前本地开发服务上进行了只读浏览器诊断。使用独立浏览器，拦截非 GET API 请求；对照修改仅发生于该浏览器收到的模块响应，没有修改仓库源代码。下列数字是本对话诊断记录，未形成可复用基准报告，实施时必须重新采样。

| 编号 | 已观察事实 | 结论边界 |
| --- | --- | --- |
| E1 | `selectSession()` 先加载目标会话，再导航；Web AppShell 使用 `fullPath` 作为组件 key | 一次导航使已展示目标内容的工作台卸载并重建 |
| E2 | 同组会话切换：原实现最长任务 1297ms，临时稳定 key 后 581ms，再临时禁用滚动同步后 460ms | 支持重建和滚动同步参与阻塞；单次实验不是优化后的 P95，也不是发布验收 |
| E3 | 同一批 7 份文档请求从 14 次变为 7 次；工作流目录从 10 次变为 5 次 | 取消重建能减少重复工作，仍需解决卡片各自请求 |
| E4 | 为 B 的历史 GET 注入 1200ms 延迟；依次选择 B、C，最终页面回到 B | 旧切换完成后仍能导航，是确定性竞态；延迟为测试注入 |
| E5 | 目标长会话有 1571 条事件、约 34176 个页面 DOM 节点；一次切换滚动同步 20 次、累计约 934ms | 长历史是切换成本放大器；计时包含布局，不能与长任务耗时相加 |
| E6 | 部分确认操作完成后无条件 `loadSession(id)`；发送完成后 `reconcileSessionEvents(id)` | 静态发现业务回调可能抢占选择或连接，需要单独自动化复现 |
| E7 | 系统一个采样点 CPU 约 17%、可用内存约 5.4GB，未观察到换页读入 | 不能证明持续资源耗尽，也不能排除瞬时系统/图形问题；操作系统光标卡顿仍待同时间线验证 |

## 3. 范围与非目标

### 范围

- Web 会话导航和初始化，关联的新建后跳转、删除/归档后选择、前进后退、直接链接。
- 页面读取取消、过期响应隔离；发送、确认、修订、上传等异步回调的会话归属。
- 草稿、附件、能力/Agent tag、弹窗、阅读位置的隔离。
- SSE 所有权、事件补齐、后台刷新和读取去重。
- 可见窗口渲染、滚动调度、文档/差异按需加载、可重建缓存的有界管理。
- 共享 Store 和组件的桌面回归，相关合同说明、测试与性能证据。

### 非目标

- 不改变 Server 编排、Agent 调度、Runtime 切换/兜底、工作区执行与写回规则。
- 不新增后端接口、事件类型、数据库表或迁移；不裁剪服务端事件和模型上下文。
- 不在本专项接入后端历史分页：当前派生状态依赖完整事件，不能直接截取最后 N 条。
- 不更换 Vue/Pinia/Router，不将所有会话页面放入无限 KeepAlive，不靠禁止快速点击掩盖竞态。
- 不修改操作系统、驱动或本地 Runtime 安装；不把页面优化结果当作整机鼠标卡顿的证明。

## 4. 行为合同与不变量

1. 路由是用户选择的来源；只有导航协调器能激活当前会话。普通读取和业务回调不能导航。
2. 页面读取使用 `sessionId + epoch` 身份。A→B→A 中两个 A 属于不同轮次。
3. 页面取消只终止读请求/展示订阅；发送、确认、上传、修订等业务操作有独立生命周期。
4. 操作发起时固定会话、确认/修订标识、请求正文和幂等标识；回调不得重新读取当前选择来决定操作归属。
5. 已发送写请求结果未知时，不把 Abort 当作业务撤销，不自动重发或用新幂等键重试。
6. 前端断开 SSE 不停止后台 Agent；切回时补齐离开期间的事件，保留现有版本与幂等规则。
7. 不因浏览历史自动执行确认、恢复任务、启动 Runtime 或取消工作区授权。
8. 只减少同时挂载的消息，不删除历史、不改变已确认决策和未决事项的判定。
9. DOM 不存在不等于业务记录不存在；确认、复制、引用定位不得以可见 DOM 作为事实源。
10. 当前选择未就绪时展示对应目标的加载/错误状态；不得显示 A 的内容却允许向 B 发送。

## 5. 验收标准

| AC | 必须满足的结果 |
| --- | --- |
| SN-AC01 | 普通会话切换不重建工作台；直接链接、重复选择、前进后退、新建/归档/删除后的选择统一入口；其他管理路由不串状态 |
| SN-AC02 | A→B→C、A→B→A、迟到成功/错误/finally 均只允许最新轮次控制展示与连接；1200ms 延迟回归不跳回 B |
| SN-AC03 | 读取、缓存刷新、激活职责分离；并发读取不能回退缓存版本；列表加载状态不覆盖切换状态 |
| SN-AC04 | 消息、上传、确认、修订等已提交操作在原会话继续；回调不抢路由/SSE、不重复执行，不污染其他会话忙碌或错误状态 |
| SN-AC05 | 文本、附件、`/`、`@`、阅读位置隔离；已提交与未提交确认区分；本地授权不被导航清理误取消 |
| SN-AC06 | 每标签页至多一个当前会话展示 SSE；旧轮次不能关闭新连接；补齐不重不漏；终态保留最终同步；后台任务不因导航停止 |
| SN-AC07 | 普通切换不重复全局初始化；同资源读请求去重，跨会话不误共享；后台同步不与首轮切换争抢；版本检查和执行前安全校验保留 |
| SN-AC08 | 滚动同步每帧合并，底部不扫描全历史；位置写入节流；动态高度、窗口调整和切回不跳动；恢复回调有轮次检查 |
| SN-AC09 | 消息挂载量随可视区而非全部历史增长；大文档/差异也受控；流式内容、焦点、既有复制/定位和确认语义不退化 |
| SN-AC10 | 文档按可见/展开读取，内容版本正确；缓存淘汰只作用于可重建客户端数据，不淘汰草稿、待确认写操作或丢失事件游标语义 |
| SN-AC11 | 404、网络故障、版本不兼容、主动取消分别处理；错误属于原轮次/操作；导航错误不触发真实任务重跑 |
| SN-AC12 | Web 及 Electron renderer 共用逻辑行为一致；保留各自布局，无后端合同、数据库、Runtime 执行语义变更 |
| SN-AC13 | 固定环境正式构建达到第 6 节性能门槛，冷/热结果分开，不能用取消正常功能的诊断版本作为验收版本 |
| SN-AC14 | 固定会话集至少往返 30 次，连接/监听器/计时器无累计增长；可重建缓存遵守容量政策，内存无无界增长趋势 |
| SN-AC15 | 同步记录页面长任务和系统资源；明确鼠标现象发生范围。未解释的全局光标卡顿不能记为全部解决 |
| SN-AC16 | 逐项保存实际证据、失败及跳过；保留已有用户改动；仅在另行授权后更新运行服务或发布，不重启执行中的 Runtime 来验证前端优化 |

## 6. 性能目标与测量口径

以下为待验证目标，不是现状承诺。测量协议、标记点和样本定义以 [Checklist](../quality/session-navigation-performance-checklist-v1.md) 为准。

- 固定同一机器、浏览器/桌面版本、视口和正式构建；开发模式诊断仅作为背景。
- 输入反馈 P95 ≤100ms；已缓存完整数据的热切换 ready P95 ≤300ms。
- 本地健康后端、无人工延迟的冷切换 ready P95 ≤800ms，必须同时报告 API 耗时。
- 当前真实规模数据的切换窗口内无单个 >200ms 主线程长任务。缺少测量不能判通过。
- 构造 174、332、1571 条事件的匿名等规模回归数据，另以 5000、10000 条事件验证有界渲染；压力集不暗中省略确认、文档和工具结果。
- 5000/10000 条冷载仍完整读取事件，必须报告读取/派生成本；本专项不宣称已解决无限历史冷载。若当前验收数据无法达标，继续优化本范围内派生/渲染，不静默降低门槛。
- 每次导航工作台额外卸载/挂载次数为 0；同资源同时在途读取最多 1 个。

## 7. 风险、决策和交付条件

高风险点：保持组件实例后残留交互状态、旧业务回调抢连接、事件淘汰但保留错误游标、虚拟化后动态高度/焦点退化、共享代码影响桌面。

已明确采用分层修复，不只增加 loading，不取消业务写操作，不先引入后端分页。没有阻塞文档编写的产品选择；性能阈值是设计目标，实际运行环境和系统光标症状在验收时记录。

完成定义：所有功能门槛有证据，性能达标，共享桌面回归通过，剩余系统侧问题如实披露。文档生成、诊断成功或某一批任务完成都不等于整项交付完成。
