# Spec：Codex 式多 Agent 任务工作区

配套文档：[Plan](../design/codex-style-multi-agent-workspace-plan-v1.md) · [Tasks](../implementation/codex-style-multi-agent-workspace-tasks-v1.md) · [Checklist](../quality/codex-style-multi-agent-workspace-checklist-v1.md)。

## 1. 目标与文档状态

把已沟通确认的客户端交互固化为可实施、可验证的规格：沿用用户提供的 Codex 截图中的左侧导航、中央内容、右侧上下文分割，承载独立需求、群聊、所选工作流、Agent 执行记录和文件差异。

本文件的 confirmed 表示产品需求已在对话中确认，不代表全部验收完成。用户已授权按四件套开发；2026-09-11 已进入实现与验证。技术尺寸、内部组件名和接口补齐方式见 Plan，实际通过项及未完成项以 Checklist 的证据为准。

依据为本次用户对话与附件截图；截图中的其他项目名、消息正文和工具入口不构成功能要求。既有项目地图、UI 合同、工作流合同作为技术基线。新客户端布局以本规格为准，原 Web 管理端编辑能力继续由原模块承担。

## 1.1 两端展示边界纠正（2026-09-11）

用户明确要求 Web 保持 Web 原有效果，桌面使用已确认的 Codex 式界面。此前直接修改 Web 共享壳和样式属于实现偏差，本次在同一 deliveryId 下纠正，不新增另一套产品方案。

- SPEC-017 / AC23：Web 保留 92px 主导航、会话头像及状态、原有对话/协同看板/工作流/审计切换、浅色群聊与深色运行视图；流程编辑入口可达。不得为桌面需求修改 Web 的展示。
- SPEC-018 / AC24：桌面拥有独立 HTML、Vue 入口、路由、工作区组件和全局样式；任务记录无图标，三栏/三 Tab、只读流程目录和历史 Diff 只在桌面工作区呈现。Web 构建产物不加载桌面布局或 CSS。
- SPEC-019 / AC25：默认 `npm run dev` 一条命令构建当前桌面代码、启动后端与 Web，后端就绪后自动打开可见桌面窗口并连接当前本地后端；仅创建进程不算成功。`dev:all` 保留为别名，仅后端/Web 使用 `dev:web`，单独桌面保留 `desktop:dev`。两端独立显示；开发桌面配置与已安装客户端隔离，不承诺桌面热更新。
- SPEC-020 / AC26：按用户最新红框截图精简桌面工作台：左侧不显示流程管理、管理与设置和搜索/筛选区域；中央不显示顶部操作栏、协作计划/执行进度板及 Token 条，并释放原占位。保留新建任务、任务分类/记录、任务标题、群聊输入与消息、右侧 Agent 进度和工作流 Tab。窄屏保留侧栏切换按钮。流程目录通过群聊选流程确认卡进入，连接设置通过应用菜单进入；Web 展示不变。此条覆盖此前左侧常驻流程管理的布局约定。
- 两端复用后端、API、合同、事件归一化、状态及纯数据算法。共享管理能力可继续使用既有组件；“共用业务”不意味着共用工作区外观。
- 验收使用同一份隔离接口样本分别检查 Web 与桌面构建资源，再运行真实 Electron；既有返工、运行连接及 Agent 链修复必须保留。

## 2. 已确认决策

追加 SPEC-026 / AC32（2026-09-14）：群聊输入框提供“停止当前会话”，中断需求讨论、契约生成/修订、消息意图识别与执行中的当前会话，保留已生成消息、产物、目录绑定及未发送草稿。停止使用可恢复的 PAUSED 语义，不撤销已经完成的文件修改。等待期间禁用重复点击；收到停止确认后显示继续；停止未确认时保留错误与重试入口，禁止直接续跑。Web 与桌面共享操作组件，右侧只读群聊不放业务操作。其他会话不受影响。

追加 SPEC-027 / AC33（2026-09-14）：结构化输出仍严格校验。一次调用首次失败后最多允许一次自动纠正，纠正时限默认 5 分钟，契约生成/修订总时限默认 20 分钟并覆盖 Provider 重试；均可配置。失败次数按工具调用 ID 去重，不自动重新执行整个阶段。达到边界时请求终止对应 Runtime，保留原有检查点恢复。心跳不视为有效进展，不覆盖校验异常；90 秒无有效进展显示等待，运行失败/终态不再显示普通运行。错误字段明细不受原 200 字摘要截断限制，内容有界，不暴露原始提示词及凭据。

追加 SPEC-025 / AC31（2026-09-14）：Web 群聊、桌面中央群聊及工作流右侧只读群聊按时间顺序追加消息，最新内容位于末尾。处于底部时随新消息、流式正文及卡片高度变化自动跟随；用户向上阅读时保留位置，不被新内容拉回。离开底部后，在消息区底部中央显示可点击的浮动控件：会话正在执行时为三个闪动圆点，停止、暂停、失败或等待用户时为向下箭头；点击任一状态立即回到最新消息并恢复跟随，到底后隐藏。已知断线时不显示运行三点。按客户端、会话及中央/右侧视图隔离阅读位置，保留已有桌面阅读恢复与确认卡定位；遵循减少动画设置，不改业务状态或两端独立布局。

追加 SPEC-023 / AC29（2026-09-14）：用户选择复用已有独立 Local Runtime。`npm run dev` 打开桌面、启动 Web/后端，并在后端就绪后连接原已授权设备与工作目录；`dev:web` 同样自动连接 Runtime，但不打开桌面。不得复制凭据到桌面内置助手、创建替代设备或重新绑定目录。重复启动复用在线设备或原自动连接进程，退出服务不强杀独立 Runtime。缺少授权、平台不匹配、连接失败时给出真实提示，保留原配置。

追加 SPEC-024 / AC30（2026-09-14）：桌面应用运行期间，会话完成后显示 Windows 原生系统通知（屏幕右侧，位置与时长服从系统设置）。通知仅包含会话标题、完成状态及查看提示；点击恢复窗口并打开对应会话。切换会话、最小化、隐藏至托盘不影响提醒；完全退出后不提供离线推送。以会话 COMPLETED 事件为准，不把单个 Agent 完成、失败或取消当成功；启动不补弹历史，同一完成事件只提醒一次，再次执行完成可以再次提醒。连接与更新提供默认开启且持久化的开关、发送测试通知和发送错误提示。Web 不新增系统通知。

AC29 补充：`npm run dev:restart-server` 也必须在新后端就绪后执行原 Runtime 自动连接检查；助手此前已退出时自动拉起，不能要求用户再点击“连接”或“启动本地助手”。

追加 SPEC-022 / AC28：Web 与桌面连接同一平台时，切回窗口/页面需刷新任务列表、当前任务详情、群聊事件和相关工作流/产物数据；即使事件连接仍显示正常也要补查。已结束任务在另一端重新启动时，应重新订阅。前台每 15 秒补查，后台不轮询；只同步数据，不抢切用户选择的任务、Tab、节点或输入草稿。

追加 SPEC-021 / AC27：在群聊输入框上方显示共享的任务活动提示。当前任务处于执行阶段、对应事件流连接正常且 90 秒内有执行信号时显示“正在运行你的任务，请稍等”；连接异常、状态待确认或执行失败时改用明确提示。等待用户选择/确认、暂停、结束时不显示运行提示。两端复用同一输入框及状态判断，不重新合并工作区布局；此提示不替代模型成功或数据库健康验收。

## 3. 术语与范围

- 产品“任务”：一个独立需求的工作空间，包含群聊和全部执行历史。
- Agent 子任务：某个节点内交给具体 Agent 的执行工作。
- 流程定义：Web 端维护并向客户端提供的已发布流程及版本。
- 工作流运行：本任务实际执行某一固定版本流程的记录。
- 执行轮次：节点初次实施、返工、复验等独立 attempt。
- 产品名称不重定义现有 Session / WorkItem 的数据库关系；适配策略见 Plan。

范围包含工作区布局、只读流程目录、选流程入口、执行信息展示、通知导航、历史 Diff、必要的数据合同补齐，以及 Windows 桌面窗口、本地助手集成、安装包和受控更新。2026-09-11 用户明确要求继续完成原桌面应用交付，修正此前误将桌面封装排除的范围；沿用本四件套和 deliveryId，不另起产品方案。团队权限体系重构、全离线单机后端不在本次范围内。

## 3.1 桌面交付补齐（2026-09-11）

- SPEC-011 / AC17：Windows x64 可安装客户端，随包提供 Vue 编译资源和应用运行环境；不依赖 Vite、npm、系统 Node 才能打开。保留已有群聊/流程/Agent/Diff；桌面不能进入 Web 流程编辑器。
- SPEC-012 / AC18：首次可设置平台地址，HTTP 仅允许回环地址，远程使用 HTTPS；配置位于用户数据目录。切换平台必须先停止空闲助手，并隔离不同平台的设备、授权和页面存储。接口/SSE 使用所选平台，断线提示不得伪造在线。
- SPEC-013 / AC19：内置独立进程运行现有本地助手，支持启动、设备码授权、状态与停止；本机目录仍通过既有授权流程选择，绝对路径不回传。外部 Agent 工具及账号须真实检测，不承诺捆绑第三方 CLI。
- SPEC-014 / AC20：关闭窗口保留助手与执行，菜单可重新打开或退出；退出、切换平台、安装更新必须经过助手内部空闲停止握手。执行、目录授权、文件操作进行中拒绝停止，不能只依据页面状态或过期进度判断；不能自动重放业务命令。
- SPEC-015 / AC21：新增界面/助手通过应用版本更新，流程目录作为平台数据刷新且历史版本固定。更新源由构建配置指定、远程 HTTPS；无发布源明确未配置。禁止下载后自动退出安装，必须用户主动安装且安全停止成功。用户配置不放安装目录。
- SPEC-016 / AC22：提供构建、启动、生成安装包命令与版本验证记录。开发安装包与正式签名发布分开：签名证书、受信更新源、真实旧版升级及干净机器验收未完成时，不能宣称正式分发就绪。生产发布要求签名，不自动上传或部署。

以上为既有桌面目标的交付补齐。Windows 优先、Electron 为当前实施基线；不改变流程业务及原 AC01–AC16 的事实状态。

本次交付状态：已生成 Windows x64 本地测试安装包，打包程序通过 Electron 冒烟；连接、助手生命周期及受控更新代码已实现。当前包未签名且未启用正式更新源，生产签名升级与干净机器安装未验收；详见 Checklist AC17–22 和 [使用说明](../devops/desktop-application.md)。这不代表原工作区所有遗留验收项已经关闭。

## 4. 功能需求

### SPEC-001：任务入口与历史归属

左侧展示项目及任务历史，保留“新建任务”和全部/我创建的/收藏分类；按 AC26 不再常驻流程管理、管理设置及搜索区域，旧搜索条件不得继续隐式过滤任务。一个新独立需求进入新的任务及群聊；需求补充、返工和复验保持原任务。历史任务能够重新打开并查看群聊、流程版本、轮次、产物。不得自动删除历史，也不得把已有多 WorkItem 会话强制合并或迁移。

任务记录采用文字列表，不显示头像或装饰图标，也不保留图标占位；任务名称及状态继续展示（2026-09-11 用户补充确认）。

### SPEC-002：中央视图与右侧状态

| 场景 | 中央 | 右侧 |
| --- | --- | --- |
| 没有工作流运行 | 群聊，无三个 Tab | Agent 进度 |
| 已有工作流，群聊 Tab | 群聊与输入框 | Agent 进度 |
| 流程图 Tab，未选节点 | 所选流程的执行图 | 只读群聊 |
| 流程图 Tab，已选节点 | 图保留并高亮节点 | 节点关联任务列表 |
| 已点击列表中的任务 | 图与选中节点保留 | Agent 子任务执行详情 |
| 关闭节点任务详情 | 当前图保留 | 恢复只读群聊 |
| 工作流详情 Tab | 阶段、子任务、轮次、验证与交付记录 | 默认只读群聊 |

工作流结束、失败或取消后 Tab 仍存在。切换视图只改变展示，不重跑任务，不重置消息草稿。载入历史期间不能把“正在加载”误判为“从未有工作流”。

### SPEC-003：需求澄清、确认与选流程

系统组织需求讨论，信息不足时在群聊追问；信息充分时生成需求总结和确认卡。用户修改总结则更新后再次确认。用户确认需求后，系统展示当前可用流程供选择。用户确认启动后执行并固定版本。

不得由客户端计时、关键词或固定消息数量判定需求就绪；也不得替用户自动选流程并启动。流程管理中的“使用”只为当前已确认需求、尚未启动流程的任务绑定所选流程。没有合适任务时提示先建立任务、完成需求确认，不提供“先选流程直接创建并运行任务”的捷径。

### SPEC-004：系统流程目录与只读预览

“流程管理”列出系统推送且当前用户可用的全部流程，可查看名称、用途、版本、节点、连线和配置的 Agent。预览支持缩放、平移、查看节点信息。

客户端不提供新增、编辑、删除、发布、修改连线或拖动节点改位；不得直接嵌入具有这些操作的 Web 流程编辑器。目录的数据来自 Web 共用后端，客户端不独立生成或维护另一份定义。“系统推送”在此定义为目录来源与可见范围，不预先承诺 WebSocket 或其他传输实现。

目录加载中、为空、断线、流程已下架、版本不可用均有明确反馈。失效选择禁止启动并提示重新选择；目录更新不能替换正在运行任务的版本。

### SPEC-005：真实流程与版本固定

图的节点、连线、顺序、分支和 Agent 配置来自选中版本。运行态来自当前运行的事件及记录。需求→开发→验证→返工是业务过程示例，不是客户端硬编码的固定四个节点。

流程图不展示 Agent 社交关系，也不按名称猜测质量工程师。保持 Web 定义的粒度；一个节点只有一个任务时不虚构其他 Agent。返工路径由真实执行记录叠加并标明轮次，不能写回流程定义。启动时保存版本与定义快照，历史始终读取该快照。

### SPEC-006：节点、Agent 与执行任务

点击节点在右侧列出本次运行内该节点关联的任务及实际执行 Agent。点击任务展开任务描述、状态、当前活动、起止时间、attempt、返工原因、执行日志、测试证据和产物。

重复使用同一个 Agent 的不同节点必须分开；同一节点的多次返工必须可区分。无任务或人工确认节点展示真实空态或人工处理状态，不伪造 Agent。群聊右侧按各 Agent 展示进度，无可靠数量时展示状态与活动，不生成虚假百分比。

### SPEC-007：工作流详情

结构化展示当前运行的阶段、节点、子任务、负责人、依赖、执行轮次、验收标准、验证结论、产物及交付。可选择历史运行和历史 attempt（如果存在），当前轮次不能覆盖过去的拒绝、返工和验证记录。

图中节点任务可跳转到详情中对应条目。工作流详情承担实施追踪，流程图承担路径总览，两者关联同一运行数据。

### SPEC-008：全局文件 Diff

群聊、Agent 子任务、流程节点、工作流详情和产物列表中的变更文件入口，统一打开只读 Diff 弹窗。展示文件路径、任务/Agent/轮次、比较双方版本、行号、上下文、新增和删除行；支持左右对比与行内对比、在本次变更集合内切换文件。

| 来源 | 默认比较范围 |
| --- | --- |
| 某次实施或返工任务 | 该次执行前 → 该次执行后 |
| 最终交付产物 | 工作流开始前 → 最终交付版本 |

历史 Diff 使用不可变内容或版本引用，不使用当前工作目录代替历史。累计 Diff 需按两端内容计算，不能简单拼接各轮 patch。新增、删除、重命名、空文件、无修改都按真实操作展示。二进制或图片按能力预览；不可预览、内容缺失、被截断或过大时明确说明，不伪造完整差异。未发生变更的普通引用文件展示只读内容并标识，不冒称有 Diff。

弹窗关闭后恢复原视图、节点、任务和位置；查看不写文件、不接受 patch、不触发 Runtime。

### SPEC-009：只读群聊与通知

右侧只读群聊与中央群聊使用同一消息来源，不显示输入框，不提交确认或其他业务决策。可以复制、查看文件或“去处理”。“去处理”切到中央群聊并定位同一通知/确认卡。

群聊集中展示完整通知、原因和处理动作。流程图节点、工作流详情的待处理标识预留“去处理”入口，本期不在这些区域直接批准、返工或改派。

“群聊消息”Tab 显示未解决的待处理数量，同一 confirmation 只计一次；读过不等于处理完成。处理结果同步三处状态。新通知不自动切页、不关闭 Diff、不替换用户正在查看的历史轮次。未产生工作流时直接在群聊展示，不为通知额外创建工作流 Tab。

### SPEC-010：上下文、恢复和交互质量

按任务隔离视图选择、草稿、选中节点/任务和历史轮次。异步响应不能串到另一任务；SSE 重连补数据但不重复执行业务操作。

消息阅读建议：处于底部时跟随新消息，用户向上阅读时保留位置并提示有新消息。Tab、节点和弹窗支持键盘访问、可见焦点和关闭后焦点恢复；状态不能只靠颜色。窄窗口提供可恢复的侧栏入口，不能直接隐藏且无入口。
