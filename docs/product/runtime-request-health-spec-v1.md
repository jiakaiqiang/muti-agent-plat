# Runtime 请求健康与未知等待 Spec v1

状态：2026-09-29 核心代码已实施，确定性回归与隔离双端组件验证已执行；全故障矩阵、真实 PostgreSQL/CLI 兼容和更新门禁尚未全部通过。本文不表示功能已上线。

关联：[Plan / 系统开发方案](../design/runtime-request-health-plan-v1.md) | [Tasks](../implementation/runtime-request-health-tasks-v1.md) | [Checklist](../quality/runtime-request-health-checklist-v1.md)。

## 1. 需求方案与目标

将“时间到即取消”调整为“时间到先观察，明确异常才兜底”。已获准启动的模型调用，有真实进展时继续执行；没有进展但无法确认异常时，保留当前调用，显示“等待模型响应／状态未知”，由用户选择继续等待或停止。

核心判断对象是请求执行状态，不是思考模式。开启思考时，thinking/reasoning 是可选进展证据；关闭思考、隐藏思考内容、非流式返回时，系统不得依赖思考事件，也不得因没有思考事件判失败。

方案不承诺在完全不可观测的上游中区分慢请求与卡死。通过明确表达未知、补齐请求级观测、保护原调用及可信停止，避免误杀与重复执行。

## 2. 已确认决策与约束

| 编号 | 来源 | 决策 |
| --- | --- | --- |
| D1 | 用户需求 | 模型正常请求期间，不因平台时间预算或无输出时长终止当前调用 |
| D2 | 用户明确选择 | Runtime 在线、进程仍在，但无进展且无法查明上游状态时，标记未知并保留调用，由用户决定等待或停止 |
| D3 | 用户对思考关闭的追问及沟通结论 | 请求健康判断与思考模式解耦；缺少思考事件不等于异常 |
| D4 | 既有安全合同 | 用户停止、可信结束回执、停止未确认屏障及禁止重复执行继续生效 |
| D5 | 本专项范围约束 | 调整时间预算和静默超时，不擅自撤销明确配置的 Token、费用、工具安全硬限制及权限限制 |

关闭思考模式与取消 invocation 是不同操作。读取不到请求状态、探测超时、设备心跳过期，也不单独证明模型请求已经失败。

## 4. 范围与非目标

范围包括：共享活动/健康合同；本地 Claude/Codex；服务端 Claude/Codex 的流式与 buffered 路径；Generic LLM 普通与 tool-loop 请求；RuntimeService 和系统 RuntimeInvocation 入口；操作预算、观测 watchdog；停止、持久化、恢复；Web 与桌面共享健康状态展示。

所有业务阶段适用，包括路由、接单、讨论、brief、执行、review 等。内部正常工具轮转产生的新模型请求不等于重新启动平台 invocation，需要在同一调用内独立关联。

不包括：改用户模型或思考设置、自动重跑历史任务、代理账号池治理、新建透明模型代理、自动换模型、修改工作区授权和写回规则、重写编排引擎。Harness 仅作为交付方法，不新增 Harness 业务模块。

用户已追加授权根据四份文档开发，本轮交付包括核心代码、测试和合同同步。未执行原服务重启、真实模型请求、生产迁移、提交、发布或部署；这些动作须遵循各自授权与门禁。

## 5. 功能要求

### RH-FR01：信号分层与模式独立

区分设备/控制通道、CLI 进程、请求生命周期、模型/工具进展及终态证据。思考开关不得改变监督策略的正确性。请求已发送、message_start、active 状态、socket 在线或进程存在不能单独升级为“有模型进展”。

### RH-FR02：可选进展采集

采集正文、工具参数增量、工具进展和可用的 reasoning 活动。记录事件序号、来源、时间和计数；不保存或展示原始思考正文/签名。重复事件、回放的完整消息、固定状态和自动生成的心跳不得刷新模型进展。

### RH-FR03：能力与健康探测

Runtime 显式声明可观测能力；不支持上游请求查询时返回 unsupported/unknown，不伪造健康。探测只查询当前调用，不生成 prompt、不调用模型、不更改会话。仅探测本身超时进入未知，不终止被探测的任务。

### RH-FR04：阈值到达不直接终止

当前调用的首帧等待、静默和操作时间阈值触发观察/探测。正常进展继续；证据不足进入 unknown_wait；不得仅以累计时长、无正文或本地自发心跳决定取消。worker 排队、未预留额度、启动前预检不获得无限准入豁免。

### RH-FR05：未知等待

unknown_wait 是附加健康状态，不把 Session 强制改为 FAILED、PAUSED 或 WAIT_USER_CONFIRM，不请求暂停，也不解除活动调用/工作区占用。用户不操作时保持原调用；后续有效事件或合法结果到达可自动恢复/正常收尾。未知通知去重，不持续刷屏。

### RH-FR06：用户控制

提供“继续等待”和语义准确的停止操作。当前实现沿用会话级停止，按钮为“停止会话全部调用”，不声称单调用精确停止。继续等待只确认用户选择，不重启进程、不另发模型请求、不增加尝试额度、不回填预算。停止复用现有可信停止流程。关闭页面、SSE 断开、页面刷新不能成为取消理由。

### RH-FR07：明确异常与有界恢复

真实请求错误、明确流中断、进程失败或原生终态错误进入异常分支；瞬时错误可以按既有策略恢复，不将单次 502 无条件解释为永久失败。未获新的有效进展前，重复错误/重试通知不是健康证据。恢复尝试、纠正次数、退避和异常处置均有界，并遵守原操作额度、allowlist 与停止屏障。

连接断开是控制链路异常，不证明远端进程已停。不得把静默产生的本地 timeout 重新包装为“明确上游异常”来绕过未知策略。

### RH-FR08：预算及安全边界

健康或未知的当前 invocation 不因时间预算耗尽被杀；已用时间继续记录，持久化截止与已用尝试数不被偷偷重置。后续新平台调用仍按原准入规则执行。Token/费用/循环次数及明确配置的工具安全硬上限独立生效，命中时记录真实 policy_limit 原因，不伪装为健康判断。

普通工具/格式修复的观测时限到达也先区分进展、未知和异常；已确认的非法输出、纠正次数耗尽或用户批准的硬安全限制仍可失败。平台无法恢复已经被供应商、CLI 或基础设施终止的原请求。

### RH-FR09：结果与停止竞争

未请求停止时，unknown_wait 后迟到的合法结果可以按既有业务链应用一次。停止请求或 session generation 替换后，迟到结果只用于核对结束，不再应用业务内容。持续保留未知停止屏障，不能为了恢复 UI 启动替代调用。

### RH-FR10：持久化与双端展示

健康快照和状态版本可恢复；Web 与桌面使用相同语义，旧 SSE/快照不得回退新状态。未知不会被批量解释为所有 Agent 卡死。健康查询失败明确显示未知，不能覆盖已有可信终态。UI 不新增顶部导航或改变既有顶部精简要求。

### RH-FR11：诊断与资源约束

关联 sessionId、operationId、invocationId、内部 request/attempt、设备与状态版本；区分模型静默、探测失败、链路中断、provider retry、用户停止和硬限制。日志不含凭据、完整 prompt、思考正文/签名。定时器、缓存、事件持久化频率及 probe 并发有界。

### RH-FR12：兼容、重启与运行更新

能力不足的旧 CLI 使用可说明的 unknown_wait 降级，不恢复“无进展就杀”。新协议协商失败在启动前拒绝或按已验证兼容模式运行。重启后旧 running 记录仅作为历史观察，不能据此复活进程、重放模型或解除停止屏障。变更须覆盖 file/PostgreSQL 及源代码/构建/实例一致性检查。

## 7. 成功标准、风险与未决项

成功不是“永不显示失败”，而是健康/未知不被时间误杀、明确异常真实收尾、用户可控、停止可信且不重复执行。

无限期未知等待可能实际保留卡死请求，并占用并发槽、worktree 和资源。这是 D2 的明确取舍；用可见状态、用户停止、资源统计与启动前容量准入管理，不偷偷添加未知自动取消 TTL。

当前没有需要重新选择的产品语义问题。观察阈值和探测频率已有有限默认值；真实 CLI 能力、生产容量、全路径资源/隐私压力矩阵仍需验收，不改变 D1–D5。实施进度、真实证据和阻塞项以 Checklist 为准，不能以单元回归通过替代上线验收。

## 9. 明确异常未恢复的预算兜底补充（2026-09-29）

用户批准修复会话 `573193b7-433f-43fb-897a-39d841808774` 暴露的异常监督缺口。日志显示模型流中断及 429/502 重试，但 Runtime 控制连接保持在线；原异常又被静默观察覆盖成未知。该事实不支持“Runtime 已挂”的结论，也不支持把已知错误一直当作无异常的慢思考。

- RH-FR07/08：原生 `api_retry`、`api_error`、请求观察中的 provider 错误必须使用同一分类和实时健康状态。明确异常在收到相应真实恢复证据前持续有效；心跳、请求受理、进程存活、不支持探测及探测超时均不能清除异常。
- 恢复前尚有原预算时允许已有恢复流程等待；原截止已到且异常未恢复时执行既有有界停止兜底。正常进展或纯未知等待仍无限期保留原调用，不新增静默自动取消期限，不重置截止或尝试数。
- 模型的新输出/新工具动作可以解除 provider 故障；已在运行的旧工具回执不能单独证明 provider 恢复。明确进程退出或控制连接中断不能被迟到输出覆盖；最终结果和可信停止仍由既有业务账本判定。
- StructuredOutput 格式错误使用独立的一次纠正额度，不伪装为 provider 连接故障；成功提交后解除格式纠正提示。
- RH-FR10/11：共享双端面板展示脱敏异常类别、HTTP 状态、实际收到的重试次数、异常时间及预算停止原因，不展示原始响应、凭据或思考正文。终态不继续声称正在等待恢复。
- RH-FR12：能力以当前连接协商为准；源代码、构建完成或 `runtimeBuildStale=false` 不证明运行进程已加载新策略。实际服务更新另行批准，遵循在途调用与未知停止门禁。
