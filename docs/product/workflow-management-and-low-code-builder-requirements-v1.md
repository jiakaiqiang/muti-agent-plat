# 工作流管理与低代码编排需求文档 v1

## 1. 文档信息

- 文档状态：需求已确认，待实施。
- 目标版本：Workflow Management v1。
- 目标用户：使用多 Agent 群聊完成研发、产品、测试和运营任务的用户。
- 关联范围：工作流管理、低代码创建器、群聊选流、工作流运行、人工确认和机器人确认。

## 2. 背景

当前系统已经具备 Agent 管理、群聊任务契约、Agent Task 执行和基础线性工作流能力，但工作流定义、确认方式和运行过程仍存在以下问题：

- 用户缺少统一的工作流列表，难以了解已有流程及涉及的 Agent。
- 创建工作流主要围绕 Agent 顺序，无法以低代码方式配置人工确认和机器人确认。
- 用户确认需求后，工作流选择入口不够集中，无法快速比较可用流程。
- 每个 Agent 完成后隐式等待人工确认，确认逻辑没有成为可复用、可配置的流程节点。
- 工作流定义和运行实例缺少清晰的版本边界，修改流程可能影响历史运行的可追溯性。

本需求将在现有业务上形成独立的工作流管理能力，并让群聊任务按照用户选定的已发布工作流流转。

## 3. 产品目标

- 提供统一的工作流列表、创建、编辑、发布、归档和查看能力。
- 使用浅色三栏低代码创建器编排 Agent、人工确认和机器人确认节点。
- 用户确认群聊需求后，可以从弹窗中选择一个已发布工作流并启动执行。
- 工作流按照发布版本的节点顺序推进，运行状态可查看、可暂停、可恢复、可审计。
- 人工确认只在显式配置的人工确认节点发生。
- 机器人确认能够输出结构化判断，异常或超限时自动转人工确认。
- 已发布版本不可变，运行实例始终绑定启动时的版本快照。

## 4. 非目标

v1 不包含：

- 条件分支、并行、汇聚、循环和子工作流。
- Tool、MCP、定时器、Webhook 和外部事件节点。
- 多人会签、候选用户组、审批委托和超时升级。
- 工作流模板市场、跨组织工作流共享和复杂权限模型。
- 根据能力画像自动替换工作流中的固定 Agent。
- 引入 Temporal、Camunda 等独立工作流引擎。

参考图中的分支布局仅用于后续 DAG 能力预留，不代表 v1 支持分支执行。

## 5. 核心概念

- 工作流：用户维护的流程元数据，包括名称、描述和当前状态。
- 工作流版本：一次发布形成的不可变节点与连线快照。
- Agent 节点：由指定 Agent 完成一个业务阶段。
- 人工确认节点：暂停流程，等待会话发起人做出决策。
- 机器人确认节点：由指定评审 Agent 根据规则判断是否继续、返工或终止。
- 工作流运行：某个群聊需求基于指定工作流版本产生的一次执行实例。
- 节点运行：工作流运行中某个节点的一次具体执行或确认记录。

## 6. 用户角色

### 6.1 工作流维护者

- 查看和搜索工作流。
- 创建、编辑和保存草稿。
- 配置 Agent、人工确认和机器人确认节点。
- 发布新版本或归档工作流。

### 6.2 会话发起人

- 确认 Task Brief。
- 选择本次需求使用的工作流。
- 处理人工确认节点。
- 查看执行进度、返工原因和最终结果。

### 6.3 执行 Agent

- 接收工作流激活的任务。
- 使用上游节点输出作为执行上下文。
- 返回阶段输出、证据和执行状态。

### 6.4 评审 Agent

- 在机器人确认节点中检查上游输出。
- 按固定结构返回通过、返工或拒绝结论。

## 7. 总体用户流程

```text
维护者创建工作流草稿
  -> 从左侧添加 Agent / 人工确认 / 机器人确认
  -> 在右侧配置节点
  -> 校验并发布版本

用户在群聊确认需求
  -> 系统弹出工作流选择窗口
  -> 用户选择已发布工作流
  -> 系统创建工作流运行和版本快照
  -> 按节点顺序执行
  -> 遇到人工或机器人确认节点时按规则处理
  -> 所有节点完成后完成会话交付
```

## 8. 工作流列表需求

### 8.1 页面内容

列表至少展示：

| 字段 | 展示规则 |
| --- | --- |
| 工作流名称 | 主标题，可进入详情或编辑页 |
| 工作流 ID | 次级信息，用于审计和问题定位 |
| 涉及 Agent | 按流程顺序展示 Agent 标签，超出数量折叠为 `+N` |
| 描述 | 单行或双行摘要，超出省略 |
| 更新时间 | 展示最后一次草稿保存、发布或归档时间 |
| 状态 | `草稿`、`已发布`、`已归档` |
| 操作 | 编辑、查看版本、归档；无历史引用的草稿可删除 |

### 8.2 搜索与筛选

- 支持按工作流名称和描述搜索。
- 支持按状态筛选。
- 默认按更新时间倒序排列。
- 空结果需要提供清空筛选和创建工作流入口。
- 页面右上角提供“添加工作流”主操作。

### 8.3 状态规则

- 草稿可以编辑，但不能在群聊中选择执行。
- 已发布工作流可以在群聊中选择；继续编辑时创建新草稿，不覆盖已发布版本。
- 已归档工作流不允许启动新运行，但历史运行和版本仍可查看。

## 9. 工作流低代码创建器

### 9.1 页面布局

创建器采用参考图的浅色三栏布局：

```text
顶部：返回、工作流名称、描述、保存草稿、发布
左侧：节点资源面板
中间：流程画布
右侧：选中节点属性面板
```

- 三栏在桌面端保持稳定宽度关系，中间画布占据主要操作空间。
- 页面不得嵌套无意义卡片；面板之间使用边界和背景区分。
- 工作流创建器是管理编辑页面，不使用运行态工作流的深色驾驶舱样式。

### 9.2 左侧资源面板

左侧固定使用三个独立分组：

#### Agent

- 展示系统中可用的 Agent。
- 支持名称搜索和分类筛选。
- 每项展示图标、名称、能力摘要和分类标签。
- 同一个 Agent 可以多次加入同一工作流，每次生成独立节点。

#### 人工确认

- 提供人工确认节点模板。
- 默认确认人为本次工作流运行对应的会话发起人。
- 资源项需要说明该节点会暂停流程并等待用户操作。

#### 机器人确认

- 提供机器人确认节点模板。
- 资源项需要说明该节点由评审 Agent 自动判断，异常时转人工确认。

三个分组允许折叠，但分组名称和资源数量始终可见。Agent 搜索不得隐藏人工确认和机器人确认入口。

### 9.3 添加节点

- 支持将三类资源拖拽到画布。
- 支持点击资源，将其插入当前选中节点之后。
- 节点连接线提供 `+` 按钮，可以从菜单中插入三类节点。
- 拖拽到两个节点之间时，系统自动重建前后连线。
- 不允许把确认节点放在开始节点之后且前面不存在任何 Agent 输出。

### 9.4 中间画布

- 使用浅色点阵背景。
- 开始和结束节点固定存在且不可删除。
- v1 只允许单开始、单结束的线性流程。
- 支持选中、移动、删除和重新排序节点。
- 工具栏提供撤销、重做、删除、对齐、放大、缩小、缩放比例和适应画布。
- 选中节点使用明确描边，节点类型使用不同图标和受控状态色区分。
- 节点和工具栏必须具有稳定尺寸，悬停和选中不能导致画布布局跳动。

### 9.5 右侧属性面板

未选中节点时，展示工作流摘要、节点数量和发布前校验结果。

选中 Agent 节点时展示：

- Agent 名称、角色、能力和标签。
- 节点名称和阶段说明。
- 输入约定和输出约定。
- 关联 Agent 为只读；需要更换时通过明确的“更换 Agent”操作完成。

选中人工确认节点时展示：

- 确认标题和确认说明。
- 向用户展示的上游输出摘要规则。
- 允许操作：通过并继续、退回上一 Agent 修改、终止工作流。
- 确认人固定显示为“会话发起人”。

选中机器人确认节点时展示：

- 评审 Agent，必填。
- 评审提示和通过标准，必填。
- 最大返工次数，默认 `2`。
- 结构化输出协议说明。
- 失败、格式错误或重试超限后转人工确认的说明。

属性变化应立即更新画布摘要，但只有保存草稿或发布成功后才写入服务端。

### 9.6 保存、校验与发布

- 工作流名称必填，大小写不敏感唯一，最多 100 个字符。
- 描述最多 500 个字符。
- 保存草稿允许暂时保留未完成配置，但必须提示未完成项。
- 发布前必须校验空流程、断链、环路、失效 Agent、确认节点没有上游 Agent、机器人确认缺少评审 Agent 或通过标准。
- 校验失败时禁止发布，并同时在画布节点和右侧校验区定位错误。
- 发布成功后形成新的不可变版本。
- 修改已发布工作流时基于最新版本生成草稿，不直接覆盖运行中的版本。

## 10. 节点业务规则

### 10.1 Agent 节点

- 节点激活时创建一个分配给指定 Agent 的任务。
- 第一个 Agent 接收已确认 Task Brief；后续 Agent 同时接收 Task Brief 和上游节点输出。
- Agent 完成后保存结果摘要、关联产物和证据，然后自动进入下一节点。
- Agent 节点完成后不再隐式要求人工确认；只有显式人工确认节点才暂停用户操作。

### 10.2 人工确认节点

- 激活后暂停工作流，并在群聊中生成待处理确认卡片。
- v1 仅允许当前会话发起人处理。
- “通过并继续”完成确认节点并进入下一节点。
- “退回上一 Agent 修改”携带用户意见返回最近的上游 Agent 节点。
- “终止工作流”将运行置为 `cancelled`，并记录操作人和终止原因。
- 同一节点的重复提交必须幂等，不能推进两次。

### 10.3 机器人确认节点

- 激活后调用配置的评审 Agent。
- 评审 Agent 必须返回：

```json
{
  "decision": "approve | revise | reject",
  "reason": "判断原因",
  "revisionInstruction": "需要修改时的具体要求",
  "evidenceRefs": ["证据引用"]
}
```

- `approve`：完成确认节点并进入下一节点。
- `revise`：将修改意见发送给最近的上游 Agent 节点并重新执行。
- `reject`：将工作流运行置为 `failed`，并记录拒绝原因。
- 返回格式错误、调用失败或超过最大返工次数时，创建人工确认并暂停工作流。
- 机器人评审输出、使用的标准和回退原因必须进入审计事件。

## 11. 群聊选择工作流

### 11.1 触发时机

- 用户点击“确认需求”并成功确认当前 Task Brief 后，系统进入 `WAIT_WORKFLOW_SELECT`。
- 前端立即打开工作流选择弹窗。
- 用户关闭弹窗时不得启动任务，会话继续保持等待选择状态。

### 11.2 弹窗内容

- 只展示已发布且未归档的工作流。
- 支持按名称搜索。
- 每项展示名称、描述、版本、Agent 顺序、人工确认数量和机器人确认数量。
- 默认不自动选择第一个工作流。
- 没有可用工作流时，提供“创建工作流”和“取消”入口。

### 11.3 启动规则

- 用户选择工作流并确认后，系统创建工作流运行。
- 运行绑定选中版本的完整快照；后续发布新版本不能改变本次运行。
- 同一个确认请求重复提交时只能创建一个工作流运行。
- 创建运行失败时，会话继续保持 `WAIT_WORKFLOW_SELECT`，并向用户显示可重试错误。

## 12. 运行状态与可见性

### 12.1 工作流运行状态

- `running`：正在执行 Agent 或机器人确认节点。
- `waiting_human`：等待人工确认。
- `completed`：所有节点完成。
- `failed`：执行失败或被明确拒绝。
- `cancelled`：用户取消运行。

### 12.2 节点运行状态

- `pending`、`running`、`waiting`、`approved`、`revision_requested`、`completed`、`failed`、`skipped`。

### 12.3 展示要求

- 群聊中展示节点开始、节点完成、确认请求、确认结果、返工和流程完成消息。
- 工作流运行视图高亮当前节点，并展示已完成和待执行节点。
- 等待人工确认时，列表和会话需要明确提示“需要用户操作”。
- 用户能够查看每个节点的输入、输出、执行 Agent、确认结论和时间。

## 13. 异常、恢复与取消

- 服务重启后能够从持久化的工作流运行和节点运行状态恢复。
- 恢复时不得重复创建已存在的 Agent Task 或重复发送确认请求。
- Agent 执行失败按照现有任务失败策略处理，并在工作流运行中记录失败节点。
- 机器人确认失败优先按节点规则转人工，不直接丢失上游结果。
- 用户取消会话时同步取消工作流运行和尚未完成的节点。
- 已完成、失败或取消的运行不能再次推进。
- 所有推进命令需要携带工作流运行、节点运行和确认请求标识以保证幂等。

## 14. 版本、归档与删除

- 发布版本不可修改。
- 工作流运行保存 `workflowId`、`workflowVersion` 和定义快照。
- 历史版本可以查看，但不能作为草稿直接修改。
- 已归档工作流不出现在群聊选择弹窗中。
- 被版本或运行引用的工作流不能物理删除。
- 无历史引用的草稿可以删除，删除前需要二次确认。
- 旧线性 Agent 工作流迁移时，为保持现有逐步确认行为，可在 Agent 之间插入人工确认节点并形成首个发布版本。

## 15. 优先级

### P0

- 工作流列表、搜索、状态筛选和 Agent 摘要。
- 三栏低代码创建器。
- Agent、人工确认、机器人确认三类节点。
- 草稿保存、发布版本和归档。
- 群聊确认需求后的工作流选择弹窗。
- 线性运行、人工确认、机器人确认、返工和失败转人工。
- 运行恢复、取消、幂等和审计事件。

### P1

- 工作流版本列表和版本差异摘要。
- 运行详情和节点输入输出查看。
- 旧工作流兼容迁移工具。
- 工作流使用次数、成功率和平均耗时。

### P2

- 条件、并行和汇聚。
- 多用户审批和超时升级。
- 能力画像匹配和动态 Agent 槽位。
- 模板市场、Scenario 和 Autopilot 绑定。

## 16. 验收标准

### 16.1 列表与管理

- 能查看工作流名称、涉及 Agent、描述、更新时间和状态。
- 能按名称搜索、按状态筛选并进入创建或编辑页。
- 草稿、已发布和已归档状态行为符合定义。

### 16.2 创建器

- 左侧三类资源分组清晰，搜索 Agent 时确认节点入口保持可见。
- 三类节点均可通过拖拽、点击或连接线 `+` 加入流程。
- 选中节点后，右侧只展示对应节点类型的配置。
- 撤销、重做、删除、缩放和定位不会破坏其他节点数据。
- 不合法工作流不能发布，错误能够定位到具体节点。

### 16.3 群聊与执行

- 确认需求后弹出所有可用的已发布工作流。
- 选择后按照选中版本的线性节点顺序执行。
- 没有显式人工确认节点时，Agent 完成后自动进入下一节点。
- 人工确认能够通过、退回修改或终止。
- 机器人确认能够通过、返工、拒绝，并在异常时转人工。
- 服务重启和重复请求不会重复推进或重复创建任务。

### 16.4 版本与审计

- 发布后修改工作流会产生新版本，不影响正在运行的旧版本。
- 每次节点执行和确认都能追溯到工作流、版本、运行、节点和操作者。
- 归档或删除不能破坏历史运行的查看和恢复。

## 17. 产品指标

- 工作流创建成功率。
- 工作流发布校验失败率及主要失败原因。
- 从确认需求到选择工作流的平均耗时。
- 工作流运行完成率、失败率和取消率。
- 人工确认平均等待时长。
- 机器人确认通过率、返工率和转人工率。
- 单次工作流平均返工次数。
