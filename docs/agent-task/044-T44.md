# T44 确认动作分流

- 状态：completed
- 预计时间：10 分钟
- 阶段：F
- 依赖：T43

## 目标

根据 action 调用不同恢复流程。

## 实施范围

apps/server/src/modules/orchestrator、sessions；前端 ConfirmationCard

## 测试

运行 SessionWorkspace 单测。

## 验收标准

- 操作不再全部映射为 resume。
- 测试结果必须记录在本文件的“完成记录”中。

## 完成记录

- 结果：前端 `SessionWorkspace` 识别结构化 Post Review action 后调用专用 store API，不再将四个选项统一映射为 resume；服务端从对应确认事件取回权威动作详情，并分别执行补读工作区、受限交付、保存进度和取消流程。受限交付会携带 limitations 跳过重复 Post Review 并进入最终交付，补读动作会登记缺失路径后重新调度。
- 验证：新增测试在实现前按预期失败（缺少前端分流 helper、SessionsService 动作处理方法，且受限交付仍会重复 Review）；实现后前端 `SessionWorkspace.spec.ts` 与 `ConfirmationCard.spec.ts` 2/2 通过，服务端 Sessions/Orchestrator 组合测试 19/19 通过，`npm run typecheck --workspace=@agent-cluster/server`、`npm exec --workspace=@project/web -- vue-tsc --noEmit` 与相关 `git diff --check` 均通过。根目录直接运行 `tsx --test` 因未加载 Nest 装饰器配置失败，改为在 `apps/server` 下按仓库约定入口复跑后通过。
- 备注：新增 `POST /api/sessions/:sessionId/post-review/actions` 合同；客户端仅提交 `confirmationId` 与 action key，服务端以确认事件中的动作对象为准，避免客户端篡改 missingPaths 或 limitations。
