## 完成记录

- 结果：新增不透明 `WorkspaceRevision`（`id`、`observedAt`）与带 `sha256` 算法标识的 `FileHash` 合同；文件元数据使用判别联合确保普通文件必须携带 hash、目录不能伪装文件 hash。list/stat/read/search 的结果均携带观测 revision，read 同时返回内容 hash，可直接比较预期与实际版本进行冲突检测。
- 验证：先新增 revision/hash 合同测试并运行 shared typecheck，按预期报告新类型缺失且四类结果不接受 revision；实现后 `npm run typecheck --workspace=@agent-cluster/shared`、T47/T48 两个合同文件执行与相关 `git diff --check` 均通过（仅有既有行尾转换警告）。
- 备注：revision 作为 Provider 生成的不透明标识供跨实现比较，文件 hash 固定声明算法，避免调用方误把不同摘要算法的字符串直接比较。
