入口：[Spec](../product/session-navigation-performance-spec-v1.md) | [Plan](../design/session-navigation-performance-plan-v1.md) | [Checklist](../quality/session-navigation-performance-checklist-v1.md)。

## 1. 执行规则

- 每项按约 10–15 分钟的专注工作单元规划，不是工期承诺；测试进程实际运行时间另记。若工作超出单元，先拆为如 T08a/T08b 的子项，继承依赖和 AC，不通过省略测试强行完成。
- 每项都按失败/预期证据 → 最小改动 → 定向验证 → Checklist 回填执行。没有证据不打勾。
- 所有拟新增文件是计划产物，不表示已经存在。开发前保存范围内已有 diff 的清单/摘要，逐块增量修改，禁止覆盖用户原有变更。
- allowedPaths/forbiddenPaths 以 Plan 第 2 节为准；文档阶段不执行下列开发动作。任务清单不授权真实群聊操作、服务重启、提交或发布。
- 测试使用匿名 fixture、隔离端口/数据目录和 mock/stub Runtime。测试脚本接入既有服务前必须检查其写入与清理行为，不默认使用当前用户服务。
- 关键 AC 不能以 mock 的单测替代实际浏览器/桌面测量；不可通过删事件、放松断言、自动确认或取消正常滚动功能达标。

第二批门槛：导航与连接只有一个所有者；不得只修 router 而留下旧 Store/定时器写入漏洞。

## 4. 第三批：群聊操作不受导航影响

- [ ] **T13 — 操作身份及忙碌状态（15 分钟）**。在客户端内部定义原会话 operation 身份，busy/error 按会话与操作管理，保留请求幂等标识。验证：A 忙碌不无故锁住 B，导航不取消写请求。依赖：T06、T08。覆盖：SN-AC04。
- [ ] **T14 — 消息发送回调（15 分钟）**。修改 `sendUserMessage` 等调用者：响应写原会话，非当前会话不接管 SSE；成功不能清空后来新写的草稿。验证：发送→切换→迟到成功/失败、结果未知不自动重发。依赖：T11、T13。覆盖：SN-AC04、SN-AC05。

- [ ] **T16 — 修订和其他写操作回调（15 分钟）**。迁移文件修订、Brief 修订、复盘等 T01 清单中的剩余隐式 loadSession 调用。验证：原任务继续、无重复提交；搜索清单中已无未解释的业务激活路径。依赖：T15。覆盖：SN-AC03、SN-AC04。
- [ ] **T17 — 附件操作归属（15 分钟）**。上传/识别重试/预览绑定发起会话和草稿版本；pending 资源不因导航释放。验证：A 上传中切 B，回执只入 A；删除/释放时正确回收 URL，刷新无法恢复 File 时不显示虚假成功。依赖：T13。覆盖：SN-AC04、SN-AC05。

## 8. 依赖与交付政策

关键顺序：T01–T05 建立证据 → T06–T12 导航所有权 → T13–T19 业务隔离 → T20–T24 读取治理 → T25–T30 展示治理 → T31–T36 验收。

表内依赖是最小前置条件；多项触及相同 Store 时按顺序执行。本清单不要求或授权派生代理。每批退出不等于专项完成；性能未达标或群聊回归失败时停止交付，回到相应任务修复。

实施证据统一进入 Checklist，不在四份文档中分别维护冲突的“完成”状态。无需修改 Server/DB；若必须扩大范围，先更新 Spec/Plan 并获得用户确认。
