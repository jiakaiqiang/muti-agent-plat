# 纠错后的版本化草稿更新

Run-id：SDD-2026-10-20-brief-correction。依据 Spec IRC-R01/R10 与 AC01/10/13 的新上下文、Brief 和执行版本要求，继续实施 IR06/IR08/IR09；整体目标保持进行中。

## 实现

此前纠错已替换 Decision，但当前草稿仍是旧版本。本轮在无执行效果纠错的激活事务中，从合法纠错计划派生 prepare_brief，绑定被替代的 Brief ID/版本、新 requirementRevision、executionEpoch、Decision hash 和意图版本。仅当当前任务正在等待草稿/工作流确认或正在修订时生成替代草稿；其他运行阶段不被强制切换。

旧草稿和旧确认收据保持不可变，旧未决确认卡标记为被修订。新草稿按 supersedesBriefId 关联旧稿；替代目标在领取、保存和发布时重验，发布事务同时推进当前草稿、确认卡、步骤和 Outbox。无草稿的会话不创建空的草稿记录。完成结果仍可在发布失败后恢复，恢复不重复模型调用。

生成使用新版本的 sourceEventId 与 snapshot，不能错误复用原始路由的旧消息；工作目标保留，当前消息为纠错原文，L5 只带有效 Decision。由于替换记录 kind 为 correction，新增约束投影沿 supersedes/overrides 追溯原分类：旧约束被替换后，新内容仍属于约束；需求替换、缺失来源与循环不提升为约束。继承约束覆盖只影响子任务，父任务和兄弟保持原值。

暂停时只保存 queued 步骤，不创建运行调用、不开始生成预算、不打开准入；恢复后由同一持久化执行器处理。再次纠错会使之前生成的迟到结果失效，不能覆盖最新草稿。Sessions 缓存同步修订检查点，保留本地暂停状态。

## 失败与范围

测试夹具初次省略 API 要求的显式 null 字段，修正夹具后进入真实逻辑。夹具还继承了示例的错误 goal，已明确绑定测试原文。类型检查发现共享语义输出为 readonly，改为一次性构造测试对象。一次 HTTP 在失败构建的输出上运行，仅保留诊断，不计最终证据；最终 HTTP 在成功构建后重新执行。全量回归发现查询 helper 创建空草稿集合，已改为不写入的查询并重跑。全部早期日志保留，最终通过范围以 manifest 为准。

本轮完成既有版本化纠错 API/聊天管线的草稿投影。尚未接通完整的结构化“修订草稿”表单（含逐题回答与指派）、生成预算耗尽后的显式恢复入口、确认后的版本化专业工作流、全部相关/独立任务与效果执行器。真实双端 Electron/SSE、CLI/数据库 HTTP/故障矩阵、完整 58 场景、500+ 双人独立标注和三轮模型评测、发布门仍待完成。IR06/IR08/IR09 和 AC 不因此整体勾选；没有提交、部署、生产数据库或个人连接变更。
