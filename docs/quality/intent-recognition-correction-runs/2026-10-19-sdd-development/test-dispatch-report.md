# 版本化测试派发开发与验证报告

本轮依据意图识别与纠错 Spec、Plan、Task、Checklist 及系统开发设计，实现单步骤测试计划的真实派发。承接 `test-runner-binding-report.md`，不把这一增量视为整套系统或完整 IR05/IR06/IR09 验收完成。

## 当前行为

1. 新合同消息在明确指向既有 WorkItem、有效独立测试授权、受支持的 server_local 绑定和开放业务准入时，可以提交一个 `enqueue_follow_up` / `run_tests` 计划。授权、运行时或状态不满足时不启动测试；暂停不会隐式恢复。
2. `IntentTestExecutorService` 为计划保存租约、120 秒总时限、一次物理调用身份和使用次数，通过 RuntimeInvocation → InvocationResolver → test_runner → TestRunnerTool → 隔离 runner 执行。普通业务 Coordinator/任务/Brief 队列不消费这一步。
3. 新增专用 `cap-isolated-test` / `tool.isolated_test`。候选检查只暴露 `run_test`，工作区权限只要求 test，不要求或授予 command。实际工具先用持久化调用、步骤和当前 grant 核验脚本/镜像/目录；伪造工具上下文或旧调用不能绕过这层检查。旧合同命令审批保持原行为。
4. 运行中的授权撤销/重签在提交后通知本实例定向 abort；幂等重放也修复丢失的通知，同时不会取消已使用当前新授权的调用。其他实例仍通过 10 秒续期校验发现变化。源码和产物写权限不随测试权限获得；新通道不输出 artifact_created 或提交 changedArtifacts。
5. 发布结果时，在同一个 File/持久化事务中重新核验当前版本、工作项、grant、操作身份、镜像绑定和已确认停止的执行日志。只发布有确定结果的测试完成通知；失败、丢失或过期结果保留审计。旧执行不能把新意图版本的 actionStatus 改成失败。
6. 恢复扫描在应用完成初始化后启动。已有完整结果可在发布事务失败/重启后补发一次；没有结果或停止未知时先对账，最终明确失败，不创建替代物理调用、不重置预算。两实例竞争只获得一个步骤租约。

授权面板的 Web/Desktop 共享文案已更新：新测试请求按当前计划处理，旧请求不会因重新授权自动重跑。

单元与故障注入进一步覆盖：两实例争抢、结果发布前撤销、发布落盘失败回滚、从磁盘恢复补发、无结果不重跑、未知停止先对账、暂停不恢复、迟到结果不能修改新版本，以及授权通知丢失后幂等恢复。最终相关回归 **104/104** 通过。
