# 运行中隔离测试的纠错对账报告

本轮依据意图识别与纠错 Spec、Plan、Task、Checklist，承接 `test-dispatch-report.md`，补上运行中测试停止后的效果对账。整个专项仍在实施；此增量只允许旧隔离测试清理后激活事务内纠错，新纠错计划携带测试执行的派发仍待接入。

## 行为与约束

- 纠错先持久化 hold 和 epoch，再停止受影响调用。运行时返回“停止成功”不能单独放行。服务端核对历史不可变计划、工作项/执行绑定、独立测试 grant、调用身份、镜像、脚本、容器名，以及持久化清理结果。
- 仅受限 `run_tests` 的 scratch 已确认清理、操作无活动调用、停止无不确定状态、且没有对应写回记录时，才生成 `isolated-test-reconciliation-v1` 收据并进入新意图校验。结果丢失可证明临时效果已清理，但不能声称测试成功或外部效果已回滚。
- 新版本激活事务重新读取上述证据；若分类期间证据变化，清除旧对账收据并保持屏障，不生成新版本。合法事务内纠错会同步路由的当前语义计划，避免展示已被取代的旧计划。
- 支持的待清理状态每 10 秒检查一次，自动检查窗口固定为接收后 120 秒；恢复不重置分类次数或截止时间。进程重启会检查可恢复记录；同幂等键 API 重放可重新触发检查。不支持或无法证明的效果继续留在待对账状态。后台定时器随模块关闭清理。
- 修复重新授权后多份历史 grant 版本造成的 `INTENT_AUTHORITY_CONFLICT`：先排除历史读取/测试授权，再处理其他继承授权的冲突；读取/测试只使用当前 Session 的有效授权。

## 验证题目

| 场景 | 断言 |
| --- | --- |
| 运行中纠错为“改为只记录测试要求，暂不运行” | 实际容器先停止并清理，随后激活版本 2，旧测试结果不发布 |
| 停止回执已成功但执行日志仍活动 | 不分类、不解除屏障 |
| 分类期间清理状态再次变成不确定 | 激活事务拒绝，保留版本 1 和 hold，清除过期收据 |
| 缺历史版本、缺授权、错误调用/容器/镜像/脚本、不同效果范围或存在写回 | 拒绝自动对账 |
| 容器清理完成但结果丢失 | 可记录 scratch 已丢弃，明确 resultKnown=false |
| 同键重放并重启真实服务 | 只有一次激活和一次旧物理调用 |
| 撤销、重新授权后连续提交新测试 | 使用当前授权，不因历史 grant 版本不同误报冲突 |

HTTP 使用真实 localhost Nest 服务、File 持久化、固定本地 Node Docker 镜像和确定性分类服务；容器经 Docker inspect 确认运行后才发送纠错。它验证程序行为，不证明真实模型意图准确率。TC01、TC02 与既有 TD01–TD07 共 9 项；包含真实服务进程重启。

## 失败与修正记录

1. 首次 HTTP 执行在第四次测试请求复现历史授权误冲突，尚未进入纠错。修正授权过滤顺序并增加连续请求回归。
2. 第二次 HTTP 已通过运行中纠错，但测试辅助函数停止服务时删除了准备复用的状态文件，后续启动报 `CUTOVER_REQUIRED`。改用独立的第二份重启快照，未改变生产迁移规则。
3. 新增测试曾直接修改只读 evidence 属性导致类型检查失败，改为构造新的 evidence 数组。
4. 首次后端全量回归为 2092 通过、1 失败、26 跳过；失败来自旧 worktree 测试清理临时目录的 Windows `EBUSY`。该文件单独重跑 10/10 通过，首次日志保留，不记为成功。
