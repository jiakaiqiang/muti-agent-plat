# 草稿生成失败后的显式重试

Run-id：SDD-2026-10-20-brief-retry。继续 IR06/IR09/IR10 的失败恢复实施，整体目标保持进行中。

## 行为

已验证的无工具草稿生成失败后，用户可通过两端共享入口“重新生成草稿”发起新的有限预算操作。请求仅含 epoch、原步骤、意图版本、路由 revision、旧 operation ID 与幂等键，不接受权限或模型结论。服务端事务重验原计划、当前任务/Decision hash/需求版本、generation、停止状态和准入。暂停、纠错 hold、未知停止、过期绑定、已完成和已有保存结果均不可新开调用。

同一逻辑步骤保留原不可变计划，新增 operation ID 与只追加收据；收据保存旧失败和完整 processing，包括原 deadline、attempts 和修复反馈。相同请求只返回原收据，新请求必须匹配当前操作和路由版本。旧操作在 Runtime 准备/预约处拒绝，不能借相同 step ID 跨重试代次启动。新操作仍为两次调用和最多 120 秒；刷新、恢复与自动格式修复不重置该预算。

POST `/sessions/:sessionId/intent-plan-steps/:stepId/retry-brief` 返回 202 受理，GET 同路径前缀 `/brief-recovery` 查询状态。查询复用实际版本守卫但不领取步骤或改变预算。发布沿用现有事务草稿存储；成功只生成一份待确认草稿，不授予任务执行权限。调度等待同实例旧 processing Promise 结束，避免重试受理刚好落在上一执行清理期间而丢失唤醒。

失败事件携带原步骤恢复引用；Web/Desktop 时间线接同一面板和 Store。未知响应保存 sessionStorage 原请求，刷新后必须显式核对；409 刷新而不重发，错配回执保留待核对请求，迟到旧读取不倒退新版本。已保存结果不允许重生成，仍走原发布恢复。

## 失败记录与限制

首次 HTTP 使用 401 后立即恢复 provider 的夹具，实际 Runtime 仍处于两分钟连接等待期，新操作被拦截且没有第二次 provider 请求。该日志保留为连接保护证据；它不证明认证修复后的恢复成功。最终 HTTP 改用格式预算耗尽验证显式预算恢复，没有关闭或绕过连接保护。当前状态查询未展示连接等待剩余时间，仍可能受理随后被连接保护阻止的操作，面板提示先修复连接；这是待完善的用户反馈边界。

首个测试命令引用不存在的独立 guard 测试文件，未执行用例；改用实际 Runtime/LogicalOperation 测试。新收据最初含 undefined 字段，File 重载后形状不同，现只保存存在字段，重启后收据严格相等。类型/构建与测试失败日志保留。
