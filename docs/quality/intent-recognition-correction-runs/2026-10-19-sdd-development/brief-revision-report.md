# 结构化草稿修订与逐题回答

Run-id：SDD-2026-10-20-brief-revision。继续实施四份文档的 IR06/IR08/IR09/IR10，覆盖 IRC-AC01/10/13/15 的部分链路；整体专项仍在实施。

## 实现与边界

已有“修订草稿”入口接入 `intent-brief-revise-v1`。请求绑定原会话、epoch、Brief ID/版本、意图版本、确认卡和幂等键，严格拒绝未知字段、陌生问题和过期目标。受理事务只保存原消息、不可变修订绑定及待处理标记；不提前确认答案，不创建权限或执行任务。相同请求在目标变化后仍可重放原收据，不同请求不能并发覆盖正在处理的修订。

统一分类管线读取完整原文和服务端绑定。提交事务要求同一任务的单段信息、约束或纠错计划且无执行效果；模型把修订解释为新任务或其他目标时阻止提交。修改说明和逐题回答分别保存：说明保持原文，答案以 question/answer Decision 入账并替换该问题的旧有效答案。重新计算 Decision hash 后派生 prepare_brief，生成新稿时移除已有确认答案的问题，原稿和历史确认收据保留。

待修订标记阻止旧稿确认；新稿发布原子解决旧确认卡。暂停提交保持暂停，草稿步骤等待显式恢复。Web/Desktop 共用 Store，在 sessionStorage 保留未知提交结果的原请求，刷新后只重试相同内容；409 清除失效请求并刷新。客户端操作绑定原消息所在会话，不随当前页面导航改变目标。

当前支持未确认草稿的无指派修订与逐题回答。指定生成 Agent 显式提示尚不支持，不能悄悄忽略选择。复杂纠错加问答、完整澄清、预算耗尽后的显式生成恢复、专业工作流及其他效果执行仍待完成；该实现边界不缩减 Spec。

## 失败闭环

首次 PostgreSQL 全组运行在旧 Outbox 测试失败：其他夹具产生的待发事件超过 100 条，而测试要求目标出现在第一批。测试现按实际批次领取直至目标出现，每批校验 ID、重复领取和空队列并保留总时限；生产批次和领取逻辑未修改。修复后同一 36 项全绿，失败日志仍保留。新 helper 的 unknown ID 类型由运行时字符串断言收窄，最终类型检查补验。

初期夹具的 dialogueAct 枚举及缺失类型导入已修正。所有初期日志保留，当前 HTTP JSON 对应最终重跑，先前本轮 HTTP 日志独立保存；未覆盖已封存里程碑证据。清理仅涉及本轮隔离容器，已确认删除，未改生产连接、提交或部署。
