# GitHub 会话手动验证规则 v1

状态：2026-09-28 当前本地开发环境已按用户要求放开入口，供手动验证；不表示专项已完整验收或可生产发布。

依据：[Spec](../product/github-session-delivery-spec-v1.md)、[Checklist](github-session-delivery-checklist-v1.md)、[本地启动说明](../devops/local-development.md)。

## 1. 环境与安全规则

- 本地 `.env` 设置 `AGENT_CLUSTER_GITHUB_SESSION_CREATE_ENABLED=true`。服务端和 Web 代理的 `GET /api/sessions/code-source-capabilities` 必须返回 `githubCreateEnabled: true`。
- 本次已重启前后端；浏览器刷新后重新打开新建会话弹窗。桌面端须连接同一后端，并使用包含 GitHub 创建表单的构建；仅重启后端不会更新旧桌面安装包。
- 使用独立测试仓库和测试分支，预先准备 README、小型源码和可重复执行的测试脚本。不要先在重要业务仓库验证。
- GitHub 来源任务在验证通过后会自动提交、推送和创建/更新 PR。合并必须由用户审查后手动点击；删除会话不会撤销远端提交、PR 或分支。
- 令牌只填会话内专用授权控件，不填任务、聊天、截图、仓库 URL 或日志。使用仅限测试仓库且权限足够的令牌；授权过小和失效令牌另作负向测试。
- 本机 GitHub 执行需要已连接且协议兼容的 Local Runtime、可用 Codex/Claude Code；服务器执行需要可用 Runtime、Git、网络及工作区隔离能力。
- 服务器保存 PAT 需要稳定的 `AGENT_CLUSTER_SECRET_KEY`；不要替换已有密钥，否则可能无法读取已有加密凭据。OAuth 需要 GitHub App 的客户端配置和 HTTPS 回调，未配置时将该项记录为“阻塞”，不能记为通过。
- 本次配置核查未发现上述服务器密钥/OAuth 配置；启动日志显示 Generic LLM 预检 HTTP 401。正式测试群聊主链路前，先在模型管理确认相关 Runtime 可用；不要用修改安全门禁来绕过配置故障。

## 2. 判定与记录规则

每项只能记录：通过、失败、阻塞或未执行。需要配置但未配置的路径为“阻塞”；界面显示成功但 GitHub 实际状态不符为“失败”。不得用 Agent 的文字说明代替实际测试退出码、PR、提交和持久状态证据。

记录格式：`编号 / 客户端 / 执行位置 / 会话 ID / 操作步骤 / 预期 / 实际 / 时间 / PR 链接与 SHA / 错误码与 requestId / 截图或日志位置`。分享记录前删去凭据和敏感路径。

## 3. 基础主链路（先执行，Web 与 Desktop 分别验证）

| 编号 / AC | 操作 | 通过标准 |
| --- | --- | --- |
| M01 / AC1、16 | 打开新建会话，分别切换本机和服务器 | 本机可选本地目录/GitHub；服务器显示 GitHub 地址输入，不要求服务器目录；历史会话仍可查看 |
| M02 / AC1、2 | 输入有效测试仓库，再试非 GitHub 地址和内嵌凭据地址 | 有效地址可创建；不支持地址被拒绝且错误不回显凭据 |
| M03 / AC2、3、4 | 创建 GitHub 会话，尚不授权，再在专用控件保存 PAT | 未授权时等待准备、不调用 Agent；有效授权推进准备，无权限/失效令牌明确阻止；OAuth 单独验证，不以 PAT 替代 |
| M04 / AC4 | 等待克隆，检查分支弹窗；分别选择实际默认分支及其他分支 | 分支来自真实仓库，不硬编码 main/master；用户确认分支并绑定完成前不开始 Agent 分析；选定后再开始讨论 |
| M05 / AC6、7 | 要求修改一个小文件并补一个测试，完成需求确认/执行流程 | 平台实际执行验证，退出码为 0 后才提交推送；自动创建 PR，目标分支正确；Author、辅助标记及 Diff 与需求一致 |
| M06 / AC7、13 | 检查完整 PR 文件列表和 Diff，暂不点击合并 | 所有页均可加载，验证结果可见；等待或刷新均不自动合并 |
| M07 / AC8 | 在同会话追加一个小改动，保持 PR 未合并 | 更新原任务分支和原 PR，不生成重复 PR |
| M08 / AC12、13 | 审查完整 Diff，确认无 CI/CI 通过后手动合并 | 使用所审查 head 的 Squash Merge；显示实际合入 SHA/文件/Diff，与 GitHub 一致；合并后再执行新改动应生成新分支/PR |
| M09 / AC1、7 | 本机选已配置 GitHub 远端的本地目录，执行小改动；另测 GitHub 无代码改动任务 | 本地目录不自动推送/创建 PR；GitHub 无改动不创建空 PR |

## 4. 异常、恢复与安全矩阵（在测试仓库执行）

| 编号 / AC | 操作 | 通过标准 |
| --- | --- | --- |
| M10 / AC6 | 让验证失败/无法运行；另用无验证脚本仓库 | 不推送；可见失败原因，缺少方式时可补充；修复并验证通过后才继续 |
| M11 / AC12 | 使用配置 CI 的仓库，分别观察 pending、failed、passed；测试保护规则 | pending/failed 禁止合并，通过后才可尝试；无 CI 不伪装成 CI 通过；GitHub 保护拒绝不能被绕过 |
| M12 / AC9、10、11 | 执行中推进基础分支；制造同文件文本冲突及删除/改名/二进制冲突 | 执行中不强制同步基础分支；需整合时列全冲突；文本三栏可编辑，其他类型可选择；逐文件确认后重新验证，更新原 PR、等待 CI、再次手动合并 |
| M13 / AC8、9 | 关闭未合并 PR、删除任务分支；另在任务分支加入远端提交 | 原 PR 可重开，原分支优先恢复；远端新提交在推送前整合，不强推覆盖；失败可见且可重试 |
| M14 / AC13 | 加载并审查 Diff 后，从 GitHub 修改 PR head，再点击确认合并 | 拒绝旧 head，要求刷新并重新审查，不合入未审查版本 |
| M15 / AC14 | 在授权、选分支、待验证、待审查或冲突草稿阶段刷新页面/重启服务；重复点击或重试 | 待用户操作、已选分支和草稿保留；不重复创建 PR/提交或合并；超时先对账远端结果 |
| M16 / AC14 | 本机 GitHub 会话断开 Local Runtime，然后重连 | 离线禁用依赖本机的操作；重连只刷新状态，不自动合并 |
| M17 / AC5 | 同仓库创建两个会话，各改不同文件；多项目仓库给模糊需求 | 独立工作区、不串改；缓存不承载会话改动；无法唯一确定项目时询问用户 |
| M18 / AC2、15 | 删除一个测试会话，再用同仓库新建会话；测试主动断开授权 | 删除仅清该会话工作区/草稿，不删除共享缓存、授权、其他会话、远端分支或 PR；有效授权可复用，主动断开后不复用 |
| M19 / AC2、16 | 查看消息、通知、错误、API 普通会话响应及分享用日志 | 不泄露令牌；通知准确；Web/Desktop 的准备、验证、PR、冲突和合并状态一致，键盘可操作 |

## 5. 停止条件与回退

发现令牌泄露、未验证即推送、未点击即合并、跨会话串改或未经审查的 head 被合入时，立即停止测试并报告，不能记录为可接受缺陷。外部清理和令牌撤销由用户在 GitHub 核查后处理。

关闭入口：将本地 `.env` 的开关改为 `false` 并重新启动开发启动器，再核对能力接口；仅重启后台业务子进程可能沿用启动器旧环境。关闭入口不撤销已发生的远端副作用，也不删除既有会话。
